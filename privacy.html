Privacy Policy

HOWORX Publishing Client

Effective: 2026-10-12

1. Who and what this policy covers

HOWORX Publishing Client is a private production and publishing tool operated by the HOWORX channel operator. This policy covers the client's handling of Google and YouTube data and this public information website. Google, YouTube, GitHub and the operator's cloud service providers also process information under their own terms and privacy policies.

Privacy contact: contact.bidnis@gmail.com

2. Google authorization and information accessed

The operator authorizes the client through Google OAuth. The client does not ask for or store the operator's Google password. OAuth access and refresh credentials are used to make authorized requests.

Google Drive: The workflow accesses the authorized account identity, selected production files, file names and identifiers, folder information and related metadata. Production material can include scripts, images, narration, captions, videos, thumbnails, quality checks and job records. The workflow reads project inputs and saves production outputs and records to the operator's Drive project folders. The current cloud authorization uses the full Drive scope. This permission is broader than access only to those project folders.

YouTube: The workflow accesses the authorized channel identity and video information, uploads videos and related media, and reads or updates authorized metadata, thumbnails, captions, visibility, publication schedules and altered or synthetic content disclosures. It records video identifiers, processing results, publication state and related execution receipts.

Analytics: A separately authorized read-only feature can retrieve aggregate video and channel performance, including views, engaged views, likes, comment counts, subscribers gained, viewing duration, audience country and traffic sources. This feature does not retrieve viewer identities or comment text.

The current cloud authorization uses YouTube management access. Other implemented local paths use upload and read-only analytics permissions. Not every workflow uses every permission. OAuth authorization does not by itself approve an unrelated upload, deletion or change of visibility.

3. Why information is used and where it is processed

Information is used to carry out the operator's selected production and publishing work, verify file and publication results, avoid duplicate uploads, diagnose failures and review aggregate performance.

The workflow uses the following services:

  • Google Drive for project files and durable production records
  • YouTube API Services for authorized channel operations and YouTube Analytics for the separately enabled reporting feature
  • OpenAI Codex cloud workspaces for selected production and automation work
  • Private GitHub repositories and coordination records for code and operational results; those records may include video identifiers, publication status and links to private project files
  • Google Cloud Text-to-Speech for selected narration text used to create speech

The operator also works with local copies on the operator's computer. Service providers receive the information required by the work performed through their services. Publication sends the selected content and metadata to YouTube; its audience depends on the visibility or schedule authorized by the operator.

The client is not a service for selling Google or YouTube API data. Stored OAuth tokens and API data are not offered to advertisers. Google API information is subject to the Google API Services User Data Policy and, for Drive data, the Google Workspace user data and developer policy, including their Limited Use restrictions:

https://developers.google.com/terms/api-services-user-data-policy

https://developers.google.com/workspace/workspace-api-user-data-developer-policy

4. Storage and protection

Depending on the execution path, OAuth credentials are held in local credential files or the operator's saved cloud environment secret configuration. The cloud refresh implementation keeps the resulting access token in memory rather than writing it to a job file.

Project files and operational records may be stored on the operator's computer, in the operator's private Drive folders, in private GitHub records and in the cloud workspaces used for the job. They are not published as part of this information website. Communication with Google API endpoints uses HTTPS.

This policy does not represent that all data remains on the operator's computer, is confined to a particular country, or is erased automatically when a cloud job finishes.

5. Retention and deletion

The operator manages stored project files and API records. The local client provides inventory and deletion controls for specified local OAuth files, upload records, analytics records and YouTube fields in local job records. It also provides a manual age-based cleanup function for supported local database records.

Those local controls do not cover cloud-held credentials, Drive copies, GitHub records, remote storage or backups. The older upload-receipt JSON cache does not support reliable age-based cleanup. A system-wide automatic deletion or expiry process has not been verified.

To request access to or deletion of information held by the client, email contact.bidnis@gmail.com and identify the relevant account or project records without sending credentials. Deletion across the local and cloud stores requires separate handling of each relevant copy. The operator must follow the applicable Google and YouTube retention and deletion requirements; this policy does not claim that running the local cleanup tool completes that process.

6. Revoking access

Google authorization can be revoked at:

https://myaccount.google.com/permissions

Revocation stops further access using the revoked authorization. It does not itself erase copies already held in the client's local or cloud stores. Request deletion using the contact address above.

Deleting the client's copies does not remove videos or other data stored by YouTube. Manage those separately through YouTube's controls.

7. This website

This information website has no public account registration, advertising features or analytics scripts. It is hosted on GitHub Pages. GitHub records visitors' IP addresses for security as described in its privacy statement:

https://docs.github.com/en/site-policy/privacy-policies/github-general-privacy-statement

The homepage loads an official YouTube branding image from Google's servers, which sends a normal web request to Google. Links to YouTube and other services take you to services with their own privacy practices.

Google's processing is described in the Google Privacy Policy:

https://policies.google.com/privacy
